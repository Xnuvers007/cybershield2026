🚪 BROKEN ACCESS CONTROL — A01:2026

Cara Kerja Broken Access Control

User bisa mengakses data atau melakukan aksi di luar izin — horizontal & vertical privilege escalation.

← File Upload🏠 Semua AnimasiIDOR →
1
👤 User biasa login ke aplikasi
User dengan role "member" login dan mengakses dashboard biasa. Menu admin TIDAK ditampilkan di UI.
2
🔍 Menemukan URL admin yang tersembunyi
Melalui directory brute-force, JavaScript source, atau menebak URL:
/admin/users /admin/dashboard /admin/settings
3
⬆️ Vertical Privilege Escalation
Akses langsung ke /admin/users BERHASIL! Server hanya menyembunyikan menu di UI tapi TIDAK memeriksa role di backend.
4
↔️ Horizontal Privilege Escalation
Mengubah parameter user_id di request untuk akses data user lain: ?user_id=admin atau manipulasi cookie/JWT.
5
🛠️ Force Browsing & Parameter Tampering
Ubah method (GET→POST→PUT→DELETE), ubah role di cookie/JWT, akses API endpoint tanpa auth. Semua adalah Broken Access Control.
6
💥 Full system compromise
Penyerang bisa: buat akun admin baru, hapus user lain, download semua data, ubah konfigurasi sistem. #1 di OWASP Top 10!

⚠️ RENTAN
// Hanya cek di frontend/UI! // Backend TIDAK memeriksa role if ($_SESSION['logged_in']) { // Semua user bisa akses admin! showAdminPanel(); }
✅ AMAN
// Cek role di SETIAP endpoint if ($_SESSION['role'] !== 'admin') { http_response_code(403); die("Akses ditolak"); } // + Role-Based Access Control (RBAC) // + Deny by default // + Log unauthorized access attempts

💀 Dampak

  • Admin takeover (create/delete users)
  • Data breach seluruh sistem
  • Ubah konfigurasi keamanan
  • Compliance failure (audit gagal)

🛡️ Pencegahan

  • Server-side auth check SETIAP request
  • RBAC (Role-Based Access Control)
  • Deny by default principle
  • Automated access control testing
