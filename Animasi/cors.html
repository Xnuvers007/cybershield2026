🌐 CORS MISCONFIGURATION

Cara Kerja CORS Misconfig

Kesalahan konfigurasi yang mengizinkan situs web mana pun untuk membaca data sensitif dari API Anda.

🏠 Semua Animasi
1
🌐 Same-Origin Policy (SOP)
Secara default, browser mencegah situs A (hacker.com) membaca respons HTTP dari situs B (api.bank.com).
2
🔓 Kesalahan Konfigurasi CORS
Developer yang malas mengkonfigurasi API agar mengembalikan header dinamis `Access-Control-Allow-Origin` yang sama dengan origin siapapun yang memintanya.
3
🎯 Mengirim Link
Korban (yang sedang login di bank) dijebak untuk mengunjungi situs penyerang.
4
📡 Fetching Lintas Domain
Situs penyerang menjalankan script JavaScript `fetch('api.bank.com', {credentials: 'include'})` secara background.
5
✅ API Mengizinkan Akses
API menjawab dengan menyalin Origin penyerang ke header `Allow-Origin`. Browser mengira ini adalah akses yang sah!
6
💥 Data Bocor
Situs penyerang kini bisa membaca respons API (misal data profil, API key) dan mengirimnya ke server mereka sendiri.
1 / 6
⚠️ RENTAN
<?php // Menerima Origin apapun secara buta! $origin = $_SERVER['HTTP_ORIGIN']; header("Access-Control-Allow-Origin: $origin"); header("Access-Control-Allow-Credentials: true"); echo json_encode(["secret" => "data"]); ?>
✅ AMAN
<?php $allowed = ["https://trust.com"]; $origin = $_SERVER['HTTP_ORIGIN']; if (in_array($origin, $allowed)) { header("Access-Control-Allow-Origin: $origin"); header("Access-Control-Allow-Credentials: true"); } ?>

💀 Dampak

  • Pencurian token sesi atau API Key
  • Kebocoran data PII (Identitas pribadi)
  • Pengambilalihan Akun (Account Takeover)

🛡️ Pencegahan

  • Gunakan Origin Whitelist yang ketat
  • Jangan pernah gunakan wildcard `*` dengan credentials `true`
  • Validasi origin secara eksplisit dengan Regex yang aman
