🔏 CRYPTOGRAPHIC FAILURES

Cara Kerja Cryptographic Failures

Kegagalan melindungi data sensitif karena kurangnya enkripsi, algoritma yang lemah, atau key management yang buruk.

← CSRF🏠 Semua AnimasiDeserialization →
1
📄 Data disimpan tanpa enkripsi kuat
Developer menyimpan password pengguna menggunakan MD5 atau Base64 di database.
2
🔓 Database bocor (Data Breach)
Melalui SQL Injection atau Backup yang tertinggal, attacker mendapatkan tabel pengguna.
3
🖥️ Attacker cracking hash
Attacker menggunakan 'Rainbow Tables' atau GPU cracking (Hashcat) untuk membobol MD5 dalam hitungan detik.
4
🔑 Password asli didapatkan
Jutaan password asli pengguna terekspos karena hash yang digunakan sudah usang/lemah.
5
💥 Credential Stuffing
Attacker menggunakan password yang sama untuk mencoba login ke akun Bank atau Email korban.
1 / 5
⚠️ RENTAN
// Sangat rentan! Mudah di-crack (rainbow table) $hash = md5($_POST['password']); // Data sensitif via HTTP biasa
✅ AMAN
// Sangat aman! Menggunakan bcrypt/Argon2 $hash = password_hash($_POST['password'], PASSWORD_BCRYPT); // Paksa HTTPS / HSTS

💀 Dampak

  • Password cracking massal
  • Pencurian data kartu kredit
  • Sniffing jaringan (Man In The Middle)
  • Sertifikat SSL kedaluwarsa/lemah

🛡️ Pencegahan

  • Gunakan algoritma modern (bcrypt, AES-GCM)
  • Jangan gunakan MD5 / SHA1
  • Selalu gunakan HTTPS (HSTS)
  • Jangan hardcode secret key
⚠️ EDUKASI ONLY
