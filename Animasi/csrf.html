🎭 CSRF — CROSS-SITE REQUEST FORGERY

Cara Kerja CSRF

Korban mengunjungi situs penyerang → browser otomatis mengirim request ke target dengan cookie session yang valid.

← Auth Failures🏠 Semua AnimasiCrypto Failures →
1
🔍 Attacker menemukan action tanpa CSRF token
Form transfer, ubah password, hapus akun — action penting yang hanya bergantung pada session cookie tanpa token verifikasi tambahan.
2
🕸️ Membuat halaman jebakan
Penyerang membuat halaman web yang otomatis mengirim request ke target:
<img src="https://bank.com/transfer?to=hacker&amount=10000000">
atau form tersembunyi yang auto-submit
3
📧 Mengirim link jebakan ke korban
"Lihat foto lucu ini!" — korban mengklik link ke situs penyerang. Korban sudah login di bank.com (cookie session aktif).
4
🌐 Browser otomatis mengirim request + cookie
Browser memuat <img> tag → mengirim GET request ke bank.com DENGAN session cookie korban. Bank.com melihat request dari user yang sudah login!
5
💸 Action dieksekusi tanpa sepengetahuan korban
Transfer bank, ubah email, hapus data — semua terjadi "atas nama" korban karena server melihat session yang valid.
6
💥 Korban tidak sadar apa yang terjadi
Uang sudah ditransfer, password sudah diubah. Korban baru sadar saat cek saldo/login. Sulit dilacak kembali.
1 / 6
⚠️ RENTAN
<form action="/transfer" method="POST"> <input name="to" value="..."> <input name="amount" value="..."> <!-- Tidak ada CSRF token! --> </form> // Situs penyerang auto-submit form ini
✅ AMAN
$token = bin2hex(random_bytes(32)); $_SESSION['csrf'] = $token; <input type="hidden" name="csrf" value="<?= $token ?>"> // Validasi: if (!hash_equals( $_SESSION['csrf'], $_POST['csrf'] )) die("CSRF terdeteksi!"); // + SameSite=Strict cookie flag

💀 Dampak

  • Transfer dana tanpa izin
  • Ubah password/email akun
  • Hapus data penting
  • Admin action atas nama korban

🛡️ Pencegahan

  • CSRF token di setiap form
  • SameSite=Strict cookie flag
  • Verifikasi Origin/Referer header
  • Double submit cookie pattern
