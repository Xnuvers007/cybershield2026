🧪 INSECURE DESERIALIZATION

Cara Kerja Insecure Deserialization

Data untrusted di-unserialize yang memanipulasi logika aplikasi dan berujung pada RCE via object injection.

← Crypto Failures🏠 Semua AnimasiMisconfiguration →
1
📦 Aplikasi menggunakan serialized object
Server PHP/Java menyimpan data session atau status pengguna dalam format 'serialized object' di Cookie.
2
🔍 Attacker memodifikasi cookie
Attacker melakukan base64 decode, menemukan property 'role=user', lalu mengubahnya menjadi 'role=admin' atau memasukkan class jahat.
3
💉 Payload di-encode ulang
Attacker merekonstruksi cookie (serialize -> base64) dan mengirimkannya kembali ke server.
4
⚙️ Server melakukan Unserialize
Server memproses data jahat dan langsung meng-instantiate object tersebut di memori.
5
💥 Serangan tereksekusi
Fungsi destruct/wakeup otomatis berjalan (Magic Methods) yang berujung pada RCE atau akses Admin diberikan.
1 / 5
⚠️ RENTAN
$cookie = base64_decode($_COOKIE['session']); // Berbahaya: unserialize object dari user $userObj = unserialize($cookie); // Mengubah property object menjadi Admin
✅ AMAN
$cookie = base64_decode($_COOKIE['session']); // Gunakan JSON yang murni data (bukan object) $userData = json_decode($cookie, true); // Dan pastikan menggunakan HMAC signature

💀 Dampak

  • Remote Code Execution (RCE)
  • Bypass otentikasi/role
  • Privilege Escalation
  • Denial of Service

🛡️ Pencegahan

  • Jangan deserialize dari untrusted user
  • Gunakan JSON bukan fungsi serialize bahasa (PHP/Java)
  • Gunakan HMAC verifikasi
  • Isolasi proses parsing
