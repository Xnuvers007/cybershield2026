⚙️ SECURITY MISCONFIGURATION

Cara Kerja Security Misconfiguration

Konfigurasi yang tidak aman, password bawaan pabrik, debug mode, atau direktori yang terbuka bebas.

← Deserialization🏠 Semua AnimasiSupply Chain →
1
🔍 Attacker melakukan scanning
Attacker menscan website menggunakan tools seperti Nmap, DirBuster, atau Nuclei.
2
📂 Menemukan folder rahasia
Directory listing dibiarkan terbuka, attacker menemukan file .env.backup atau /phpinfo.php.
3
📄 Menganalisis bocoran data
Attacker membuka debug page atau .env yang membocorkan password database dan secret key JWT.
4
🔑 Menggunakan kunci yang bocor
Attacker menggunakan secret key untuk membuat JWT (token) Admin palsu.
5
💥 Mengambil alih aplikasi
Dengan akses admin, sistem sepenuhnya dikompromikan akibat satu kelalaian konfigurasi.
1 / 5
⚠️ RENTAN
# Production Environment APP_DEBUG=true DB_PASSWORD=admin # Apache: Options +Indexes (terbuka)
✅ AMAN
# Production Environment APP_DEBUG=false DB_PASSWORD=r4nd0m_str0ng_p4ss # Apache: Options -Indexes (ditutup)

💀 Dampak

  • Exposure source code/config
  • Admin access via default credentials
  • System takeover
  • Stack trace membocorkan logika

🛡️ Pencegahan

  • Matikan Debug Mode di Prod
  • Ganti SEMUA password default
  • Hapus file backup/install
  • Terapkan Security Headers
