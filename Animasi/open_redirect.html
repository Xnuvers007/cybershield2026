↗️ OPEN REDIRECT

Cara Kerja Open Redirect

Redirect tanpa validasi → korban diarahkan ke phishing menggunakan domain terpercaya sebagai "perantara".

← Supply Chain🏠 Semua Animasi
1
🔍 Menemukan parameter redirect
URL seperti login.php?redirect=dashboard — setelah login, user diredirect ke URL yang ditentukan parameter.
2
🔗 Mengganti dengan URL phishing
Penyerang membuat link dengan redirect ke situs jahat:
https://trusted-bank.com/login?redirect=https://evil-phishing.com/fake-login
3
📧 Link dikirim ke korban
Korban melihat domain asli (trusted-bank.com) → merasa aman → mengklik link. "Ini link resmi dari bank!"
4
🔄 Server redirect ke URL penyerang
Setelah login berhasil, server redirect user ke URL yang ditentukan tanpa validasi → user masuk ke situs phishing.
5
🎣 Halaman phishing meniru situs asli
"Session expired, silakan login kembali" — korban memasukkan credential di situs palsu yang mirip 100% dengan aslinya.
6
💥 Credential dicuri
Username & password korban terkirim ke penyerang. Account takeover, financial fraud, identity theft.
1 / 6
⚠️ RENTAN
$url = $_GET['url']; header("Location: $url"); exit; // ?url=https://evil-phishing.com/login
✅ AMAN
$url = $_GET['url']; $allowed = ['example.com']; $parsed = parse_url($url); if (in_array($parsed['host'], $allowed)) { header("Location: $url"); } else { header("Location: /"); } // Atau: gunakan relative path saja

💀 Dampak

  • Credential phishing via trusted domain
  • OAuth token theft
  • Malware distribution
  • Bypass email security filters

🛡️ Pencegahan

  • Whitelist domain redirect
  • Gunakan relative path saja
  • Validasi URL scheme (https only)
  • Warning page sebelum redirect
