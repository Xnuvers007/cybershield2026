🔄 SERVER-SIDE REQUEST FORGERY

Cara Kerja SSRF

Memaksa server untuk membuat HTTP request ke jaringan internal atau eksternal yang tidak semestinya diakses.

← RCE🏠 Semua AnimasiXXE →
1
🔍 Menemukan fitur fetch URL
Aplikasi web memiliki fitur 'Import Profil dari URL' atau webhook.
2
💉 Memasukkan IP internal / Metadata
Attacker memberikan URL: http://169.254.169.254/latest/meta-data/ (AWS Metadata).
3
🌐 Server melakukan request
Server membuat request HTTP dari dirinya sendiri, membypass firewall eksternal.
4
📄 Layanan internal merespon
Layanan internal/Cloud provider percaya karena request berasal dari server (trusted entity).
5
💥 Kunci rahasia dikembalikan
Server memantulkan hasil request internal (seperti AWS IAM Tokens) kembali ke attacker.
1 / 5
⚠️ RENTAN
$url = $_POST['image_url']; // Server mendownload dari URL yang diberikan user $data = file_get_contents($url);
✅ AMAN
$url = $_POST['image_url']; $parsed = parse_url($url); // Blokir akses ke IP internal / localhost if (isInternalIP(gethostbyname($parsed['host']))) { die("Akses Ditolak"); } fetch_data($url);

💀 Dampak

  • Akses ke admin internal (localhost)
  • Membaca cloud metadata (AWS IAM keys)
  • Port scanning internal
  • Bypass firewall

🛡️ Pencegahan

  • Validasi IP address ketat
  • Hindari URL fetch berdasarkan input user
  • Gunakan network segmentation
  • Disable redirects di client HTTP internal
