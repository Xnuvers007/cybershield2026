📦 VULNERABLE & OUTDATED COMPONENTS

Cara Kerja Supply Chain Attack

Menggunakan library pihak ketiga (NPM, PyPI, Composer) yang rentan atau disusupi backdoor.

← Misconfiguration🏠 Semua AnimasiOpen Redirect →
1
📦 Developer menginstall library
Developer menggunakan package populer seperti 'lodash' atau 'log4j' tanpa mengecek kerentanannya.
2
🦠 Library disusupi atau rentan
Attacker menyusupkan kode jahat ke versi baru library tersebut di NPM/PyPI, atau menemukan 0-day.
3
⚙️ Aplikasi membuild dependency
Saat aplikasi di-deploy, kode berbahaya (backdoor) otomatis ikut ter-install di server produksi.
4
📡 Backdoor aktif
Kode pihak ketiga ini berjalan di background dan mencuri variabel environment (password DB/AWS Keys).
5
💥 Server dikompromikan dari dalam
Meskipun kode developer aman, aplikasi tetap hancur karena menggunakan komponen yang rapuh.

⚠️ RENTAN
// package.json "dependencies": { "log4j": "2.14.0", // Sangat Rentan (Log4Shell) "express": "*" // Selalu update versi terbaru tanpa cek }
✅ AMAN
// package.json "dependencies": { "log4j": "2.17.1", // Sudah di-patch "express": "4.18.2" // Versi dipin dengan aman }

💀 Dampak

  • Zero-click RCE (seperti Log4Shell)
  • Data exfiltration via dependency
  • Ransomware terdistribusi
  • Kredensial developer dicuri

🛡️ Pencegahan

  • Rutin audit dependencies
  • Gunakan Software Bill of Materials (SBOM)
  • Gunakan tool SAST/SCA
  • Lockfile validation
