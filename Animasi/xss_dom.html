🌐 DOM-BASED CROSS-SITE SCRIPTING

Cara Kerja DOM-based XSS

XSS yang terjadi seluruhnya di client-side JavaScript, tanpa payload terlihat di sisi server.

← Stored XSS🏠 Semua AnimasiCommand Inj. →
1
💻 Aplikasi menggunakan client-side JS
Website SPA (React/Vue/Vanilla) mengambil nilai dari fragment URL (#) atau parameter.
2
🔗 Attacker membuat link
Membuat URL: #lang=<img src=x onerror=alert(1)>
3
📧 Korban mengklik link
Karena payload ada setelah '#', browser tidak mengirimnya ke server, bypass WAF/Filter.
4
🔄 JavaScript memproses fragment
Kode innerHTML = location.hash dijalankan langsung oleh browser.
5
💥 DOM termanipulasi
Browser merender tag HTML berbahaya dan mengeksekusi onerror event di komputer korban.
1 / 5
⚠️ RENTAN
const params = new URLSearchParams(window.location.search); const name = params.get('name'); // Berbahaya: innerHTML document.getElementById('greeting').innerHTML = name;
✅ AMAN
const params = new URLSearchParams(window.location.search); const name = params.get('name'); // Aman: textContent document.getElementById('greeting').textContent = name;

💀 Dampak

  • Pencurian Data Sensitif
  • Manipulasi DOM lokal
  • Aksi tidak sah via JavaScript
  • Bypass server-side filter

🛡️ Pencegahan

  • Gunakan textContent bukan innerHTML
  • Hindari eval(), setTimeout() dengan string
  • Sanitasi DOM input (DOMPurify)
  • Audit client-side JS
